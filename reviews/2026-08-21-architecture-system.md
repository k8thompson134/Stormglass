# Architecture Review — Whole System

Date: 2026-08-21. Scope: whole-system sweep (backend ~7.1k lines, frontend ~7.0k lines), run as 11 parallel narrow-scope agents plus direct verification of every high-severity claim.

**Prior review reconciliation:** no prior *architecture* review exists — this is the baseline. The one prior file, `reviews/2026-07-27-aqi-epa-scale-and-sensitivity-settings.md`, is a QA review; both of its bugs were re-checked against current code (see D8 / Prior-review status).

**Headline:** the codebase is in better shape than its size suggests — the comments are genuinely excellent, the pure-function/`now`-as-parameter discipline in `utils/` is real, and the backend test suite is deterministic. But this sweep found **~20 live bugs**, several user-visible, and they cluster around three structural causes rather than being independent mistakes:

1. **Duplication with no enforcement mechanism.** Six things are defined 2–4 times with nothing keeping them in sync. Most are identical *today*; one (the condition list) has already drifted, causing three separate live bugs.
2. **A documented data hazard that only one module respects.** `api/weather.ts` documents in prose that `weather_data`/`air_quality_data` mix observations with 7-day forecast rows. Three other modules read those tables without the guard.
3. **A convention that exists, is documented, and is followed in 3 of ~11 places.** "Distinguish error from no-data-yet" is implemented beautifully in `AQIForecastChart`, `AQISeasonSummary`, and the notification log — and violated everywhere else.

## D4 — Abstraction quality

- **`dispatchAlert`'s config interface is the right abstraction with a leaky interface** (`push.ts:189-200`). Three of its fields — `getLastNotified`, `buildDedupUpdate`, and implicitly `subsWhere` — are three independent restatements of one fact: which column pair this alert uses. Nothing prevents `getLastNotified: sub => sub.lastNotifiedMecfsRisk` paired with `buildDedupUpdate: key => ({ lastNotifiedPotsRisk: key })`. **It type-checks and silently corrupts dedup.** Replace with a single `dedupColumn` key, keeping only `isDuplicate` as a callback (it genuinely varies). **high / m**
- **`registerAlertToggleRoutes` has the same shape problem** (`api/push.ts:33-38`) — `readEnabled` and `buildUpdate` both encode the same column pair. **med / s**
- **`recommendations[0]`-is-headline is enforced by nothing.** `HealthRisk.recommendations` is a bare `string[]`; 13 producers use 4 different construction strategies. For the seven static-array conditions the "dynamic" feature isn't dynamic — same string at `high` and `severe`. Fix shape: an explicit optional `headlineRecommendation?: string` so *absence* renders nothing instead of falling through to filler. **med / s**
- **Confusable naming with real edit hazards:**
  - `CATEGORY_FLOOR` vs `categoryCeiling` (`aqiWindows.ts:109,130`) — 20 lines apart, one is a const map (inclusive lower bound), the other a function (inclusive upper bound of the *previous* band), and they appear on the same line at `:133`. A wrong reach produces an off-by-one-category threshold on the safe-window path.
  - `findSafeWindows` / `findCategoryClearTime` / `findNextCategoryCrossing` all scan a forecast series, but their threshold args are three *different kinds of number* — raw AQI, a `CATEGORY_ORDER` **index**, raw AQI. Passing `100` where `2` is expected type-checks and silently means "never clears." Take an `AqiCategory` and `indexOf` internally.
  - `clearAqiCrossingDedupState` (`push.ts:550`, at the bottom of the file, 250 lines from its sender) vs `clearCurrentAqiBadDedupState` vs `clearClearAirDedupState` (reads as a typo).
  - Four `min*P*` variables in `PressureChart.tsx` (`minPressure`/`minP`/`localMinP`/`minPVal`), two one character apart and used four lines apart.
  - `export interface Settings` (`api.ts:169`) collides by name with the `Settings` **component**; 20 textual refs split across two meanings. Rename to `LocationSettings`.
  - `airquality.ts` vs `purpleair.ts` — both produce `usAqi`; nothing in either name says which is the regional model and which the hyperlocal overlay, or which wins.
- **`smoke.ts:16-18` — leaky/false naming.** `next24hPeakPm25`/`next24hPeakUsAqi`/`next24hPeakAt` promise a 24h horizon but `analyzeSmokeTrend` never bounds `futureRows`; both callers pass 72h. The window is the caller's secret, encoded falsely in the field name. This is the recorded "derived labels drift from their data" shape. **med / xs**
- **Over-engineering (minor):** `CurrentConditions.tsx:18-20` `severityConfig` is a one-line pass-through; `NowDot` (`PressureChart.tsx:150`) renders per data point and returns null for all but one, where a `<ReferenceDot>` expresses the intent directly.
- **Best abstractions in the repo, worth copying:** `SecondaryAlertKind` + `SECONDARY_ALERT_PATH` (`api.ts:394-423`) — four endpoints, one parameterized pair, with a comment naming the backend function that justifies it, and correctly *not* absorbing the differently-shaped main AQI toggle. And `PushEnableResult` + its exhaustive `Record<reason,string>` message map (`Settings.tsx:167`) — adding a failure reason is a compile error until you write user-facing copy.

## D6 — Coupling, cohesion & state

- **Six files import `getCurrentConfig` from `jobs/weather-poll.js`** (`briefing`, `settings`, `weather`, `correlations`, `symptoms`, `push`). The cron job module has become the de facto runtime-config singleton, so the whole API layer depends on job-module module-level state. Fix: `services/runtime-config.ts` owned by neither. **med / m**
- **Single-process assumption is nowhere enforced or documented.** `currentConfig`/`currentTask` are module-level mutables; `startWeatherPolling` is called unconditionally at boot with no stop-if-existing guard (unlike `restartWeatherPolling`), so calling it twice leaks the previous `ScheduledTask`. Two workers → double polling, duplicate rows, double alerts. `docs/architecture/SYSTEM_DESIGN.md:90-92` computes the Open-Meteo quota assuming exactly one poller. **med / s**
- **Dedup is a non-atomic read-then-write** (`push.ts:213-230`): `select` → send → `update`. `runPoll` has no in-flight guard and a slow cycle can exceed its 30-min interval, so two overlapping cycles both see the stale value and both send. Compounds with the zero-timeout finding. **med / m**
- **`vapidConfigured` is computed once at import** (`push.ts:30`) but `isPushConfigured()` is a *function*, so it reads as a runtime check and can never change. Rotating VAPID keys requires a full restart and nothing says so. **med / xs**
- **`env.ts:28-55` writes to `../.env` at import time.** Four problems: it resolves against `process.cwd()` so the file written depends on launch directory; it *appends*, so repeated failures leave multiple `API_TOKEN=` lines; on a read-only FS it only `console.warn`s and generates a **new token every restart**, silently breaking lair's `STORMGLASS_API_TOKEN` with 401s and no signal on either side; and importing a config module can `process.exit(1)`, which is why `env.ts` is untestable and every test avoids touching it. **high / m**
- **`purpleair.ts`'s cache is a single slot, not a map**, despite the comment saying "keyed by location" — two alternating locations thrash to a 0% hit rate, defeating the cost argument the comment makes. It also has no in-flight dedup (written only after `await`), so N concurrent requests at TTL expiry all fire real upstream calls — exactly the burst it exists to prevent. **med / s**
- **`db/index.ts` has fan-in of 17** and declares no pool size — the library default (10) is shared by the Fastify server, the cron job, and the WebSocket handler, with no comment recording that choice. Graceful shutdown **is** handled correctly (`server.ts:150-151`). **med / s**
- **`nowTs = useMemo(() => Date.now(), [data])`** in both charts (`PressureChart:174`, `AQIForecastChart:253`) — a deliberate lint-defeating staleness dep. Every downstream memo inherits a frozen clock, so on a tab left open the NOW line and past/forecast split stop advancing and elapsed observations keep rendering as dashed "forecast." Shared convention, so fix in both. **med / s**
- `App.tsx:100-125` — `loadData` has no staleness guard (B11), and `setLoading(true)` fires on every background refresh, so every 5 minutes both charts flip to skeletons while holding perfectly good data. The 5-min interval itself is **verified clean** (stable `useCallback`, correct deps, `clearInterval` in cleanup).

## D7 — Data & schema architecture

- **The forecast-tail hazard: one documented rule, three violations.** `api/weather.ts:33-40` and `:53-57` document in prose that `weather_data`/`air_quality_data` mix observations with forecast rows and that queries must bound `lte(timestamp, now)` *and* filter `location`. Violations:
  1. `services/openmeteo.ts` — **B1**, never converges forecast → observed.
  2. `services/snapshot.ts:52-82` — **B2**, no `lte(now)` and no `location`; every symptom log stores next week's forecast.
  3. `api/correlations.ts:372-434` — timeseries route has no `lte` bound at all, so daily means blend forecast with observed (latent; the route is orphaned).
  This is the strongest argument in the review for moving these rules out of one route's comments into a shared query helper.
- **No schema drift check exists.** Scripts are `db:generate`/`db:migrate`/`db:studio`; CI runs lint/test/build with no DB. Drift between `schema.ts`, `drizzle/*.sql`, and the live DB is purely assumed. A CI step applying `drizzle/` to a scratch Postgres and diffing against `schema.ts` covers the real failure mode of all three db files, which no unit test would. **high / s**
- **Missing index on the hottest query shape**: `air_quality_data` has only `(user_id, timestamp)`, but eight read sites filter on `location` + timestamp range. `weather_data` and `pollen_data` both got a `(location, timestamp)` index; this table — which grows fastest, being rewritten every poll — did not. **high / xs**
- **No table has a unique constraint on its natural key** `(user_id, location, timestamp)` — only non-unique indexes. So no insert is idempotent; dedup is application-level read-then-insert with no DB backstop. **The fix collapses several findings at once**: add unique indexes, then `onConflictDoNothing()` deletes all four duplicated dedup blocks and `onConflictDoUpdate()` on `weather_data` fixes B1. **med / m**
- **`push_subscriptions` is a column-per-feature table that has stopped scaling** — 17 columns, 10 of them five identical enable/dedup pairs added across 4 migrations in ~6 commits. A child table `push_alert_prefs(subscription_id, alert_type, enabled, last_notified_key)` makes a new alert type a data row rather than DDL, and collapses `dispatchAlert`/`registerAlertToggleRoutes`/the five `clear*` functions to single implementations. Worth doing before alert type seven. **med / l**
- **`push_notification_log` grows unbounded** — one `suppressed_dedup` row per subscription per alert type per 30-min poll while a condition persists (~48/device/day for one sustained condition, 150+/day with several). No delete path, no retention job, no TTL anywhere in the backend. **med / s**
- **`migrate.ts` has no partial-failure story.** Drizzle applies a file's statements without wrapping them in one transaction, so a failure at statement 4 of 6 in `0009` leaves `push_subscriptions` with three of six columns and the journal not advanced; the retry then fails on "column already exists." The catch logs and rethrows without distinguishing anything. **med / s**
- **`geomagnetic.ts:81-82` stamps one "latest" plasma reading onto all ~56 historical Kp rows** — every row claims the current solar-wind speed/density regardless of its own timestamp. Fabricated history feeding correlation analysis. **med / s**

## Candidate learnings

1. **Duplication findings are worth diffing, not counting.** The two copies flagged loudest here (`healthLogic`, AQI category math) turned out byte-identical; the one nobody was watching (the condition list, spread across 4 files) had already drifted and caused three live bugs. Divergence — not repetition — is the signal.
2. **A documented hazard with no shared helper is a hazard that gets violated.** `api/weather.ts` documents the forecast-tail rule in prose and guards its own queries; three other modules read the same tables without it, producing two critical bugs. When a rule earns a comment, that's the signal to extract it into a helper rather than restate it.
3. **An inaccurate contract comment is worse than no comment, because it terminates the search.** Four instances here (`healthLogic.ts:285`'s invariant that only holds at `severe`, `aqiWindows.ts:105`'s "calls into this" that's actually hand-copied, `HealthImpact.tsx:368`'s blend rule contradicted 15 lines later, `healthLogic.ts:1`'s "once its build is wired up" when the build is wired) each actively misdirect a reader who checks.
